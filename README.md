# dox-u

Проект на rost-rs (фреймворк), возможно как отдельная страница блога.
По SSR отдаёт все данные, которые о посетителе видит сервер (IP,
заголовки, геолокация по IP и т.д.), затем клиентский компонент
дополнительно собирает всё, что можно узнать на уровне JS без
запроса разрешений (canvas/WebGL fingerprint, шрифты, часовой пояс,
разрешение экрана и т.д.). Экспериментально пытается поймать
реальный IP через TURN-сервер (обход VPN/прокси через WebRTC).
При загрузке `/script.js` сервер сохраняет в SQLite данные запроса, включая
адрес peer-соединения. Скрипт собирает данные браузера, запрашивает IP-геоданные
у `ipwho.is` из браузера и отправляет всё одним POST на `/api/collect`.
Серверных исходящих запросов к геосервису нет; если внешний API недоступен,
визит всё равно сохраняется, а геолокация остаётся пустой.

Страница `/visits` показывает сохранённые записи SQLite: сводку по визиту и
раскрываемые JSON-данные сервера, браузера и IP-ответов.

SQLite собран в бинарник через `rusqlite` с bundled SQLite. Файл базы
по умолчанию находится в `data/dox-u.sqlite3`.

Настройки окружения:

- `PORT` — порт HTTP-сервера (по умолчанию `3000`).
- `DATABASE_PATH` — путь к файлу SQLite (по умолчанию `data/dox-u.sqlite3`).
- `DOX_MODE=collector` — вместо панели отдаётся минимальная HTML-страница,
  которая загружает скрипт и отправляет собранные данные на этот сервер.

В режиме collector внешний сайт может подключить скрипт через
`<script src="https://ваш-домен/script.js" defer></script>`.
Для такого подключения включён CORS для POST-запроса сбора данных.

Для полной работы без внешнего геосервиса понадобится локальная GeoIP-база.
Например, GeoLite2 City содержит город и часовой пояс, но занимает около 50 MB;
GeoLite2 Country меньше — около 3 MB, но не даёт город и часовой пояс. Базу нужно
обновлять отдельно. [Размеры баз MaxMind](https://dev.maxmind.com/geoip/docs/databases/city-and-country/).

Файловая система бесплатного Render эфемерная: SQLite-файл доступен во время
работы инстанса, но очищается при перезапуске или новом деплое. Для постоянного
хранения нужен подключённый постоянный диск или внешняя база данных.
